# 컨텍스트 노트

## 결정 사항

- 목록 소스: 별도 API 호출 없이 사용자가 현재 보고 있는 페이지를 파싱 (사용자가 컴맹이라 설정 단계를 최소화하고 싶어함).
- 갱신 방식: 자동 갱신 (수동 새로고침 버튼 없음). 네이버 블로그가 SPA라 MutationObserver + history 후킹 이중 감지 필요.
- 복사 내용: 순수 URL만 (제목 텍스트 없이). 스마트에디터에 붙여넣으면 네이버가 자동으로 링크 미리보기 카드로 변환해줌.

## 실제 확인된 DOM 구조 (사용자가 제공한 HTML 발췌 기반)

- outer frame: `blog.naver.com/블로그ID` → `<iframe id="mainFrame" src="/PostList.naver?blogId=...">`
- 게시글 한 건: `<a class="link pcol2" href="/PostView.naver?blogId=...&logNo=...">`
- 제목: 그 안의 `<strong class="title ell">`
- href는 상대경로 → `new URL(href, location.href)`로 절대 URL 변환 필요

## 리스크/미검증 사항

- MutationObserver 관찰 대상을 `document.body` 전체로 잡음 (더 좁은 컨테이너 셀렉터를 못 구했음). 성능 이슈 있으면 추후 좁힐 것.
- 실제 브라우저 수동 테스트는 사용자가 진행 (에이전트가 직접 크롬 확장 프로그램을 로드해서 테스트할 수 없음).

## 아키텍처 변경 (실사용 테스트 후 발견된 문제로 인한 전환)

초기 설계는 "현재 활성 탭의 실시간 목록"을 사이드패널이 그대로 반영하는 방식(content-script → chrome.runtime 메시지 → 사이드패널)이었으나, 실사용 테스트에서 두 가지 문제가 드러났다.

1. 네이버 블로그 목록이 **가상 스크롤**이라 스크롤 위치에 따라 화면에 보이는 글만 DOM에 존재. 스크롤을 내렸다 글쓰기 화면으로 이동하면 최근 글 일부가 누락된 채로 캡처됨.
2. 확장 프로그램을 `chrome://extensions`에서 리로드해도 이미 열려있던 사이드패널은 메시지 연결이 끊긴 채로 남아있어 "Could not establish connection" 에러 발생.
3. 무엇보다 사용자의 실제 니즈는 "글쓰기 화면에서도 이전에 본 목록이 계속 남아있는 것"이었는데, 활성 탭 기준 실시간 반영 방식은 본질적으로 이 요구와 충돌.

그래서 **chrome.storage.local에 발견한 글을 계속 누적 저장**하는 방식으로 전환했다.

- content-script는 카테고리 페이지를 볼 때마다 보이는 글을 `posts` 객체(url을 key로)에 upsert.
- 사이드패널은 특정 탭/프레임과 무관하게 저장소 전체를 렌더링하고, `chrome.storage.onChanged`로 실시간 반영.
- 사용자가 각 항목의 삭제(✕) 버튼으로 직접 정리 (전체 삭제 버튼은 없음, 개별 삭제만 지원하기로 결정).
- 카테고리 전환 시 초기화하는 로직은 제거함 (이제는 영구 누적이 목적이므로).
