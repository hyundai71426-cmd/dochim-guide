# Auto Blog Poster - 진행 상황

마지막 업데이트: 2026-07-08 (제목 작성 모드: 홈판용/정보 전달용 분리)

## 프로젝트 개요
PyQt5 기반 데스크탑 앱. 참고 블로그 제목들을 입력하면 네이버 실시간 검색(블로그/뉴스)을 크롤링해
사실관계를 확보하고, LLM으로 정보 초안 → 경험 관점 오버레이 → 톤 윤문 순으로 글을 생성한 뒤,
소제목별 인포그래픽 카드 이미지를 만들고, 네이버 스마트에디터원에 붙여넣을 수 있는 형태로 출력한다.

## 파일 구조
- `main.py` — PyQt5 UI + `BlogGeneratorThread`(생성 파이프라인) + `SettingsTab`
- `providers.py` — Claude/Gemini/ChatGPT/Ollama 공급자별 모델 조회(`list_models`) 및 채팅 호출(`chat`) 어댑터
- `config_manager.py` — `config.json` 로드/저장 (공급자별 API 키·Base URL·모델 저장)
- `config.json` — 실제 설정값 (최초 실행 시 자동 생성, 기존 하드코딩 Claude 프록시 키를 기본값으로 이식)

## 완료된 작업

### 1. 체크박스로 이미지 생성 on/off
"글 작성" 탭에 "썸네일 이미지 만들기" / "본문 소제목 이미지 만들기" 체크박스 추가. 둘 다 기본 체크,
각각 꺼서 원하는 것만 생성 가능.

### 2. 브라우저 미리보기 기반 복사 흐름
네이버 스마트에디터원은 raw HTML 소스 붙여넣기를 지원하지 않으므로, 결과를 `preview.html`로 저장하고
"🌐 브라우저에서 미리보기 열기" 버튼으로 기본 브라우저에서 연 뒤 Ctrl+A/C로 복사하는 방식으로 변경.
이미지도 플레이스홀더 문구 대신 실제 `<img>` 태그로 삽입(같은 폴더의 상대경로 참조).

### 3. 멀티 프로바이더 설정 탭
"⚙️ 설정" 탭에서 Claude/Gemini/ChatGPT/Ollama 중 선택, API 키·Base URL(직접 입력 가능, 프록시/공식 API
둘 다 지원)·모델을 설정. "🔄 모델 업데이트" 버튼으로 그 시점에 실제 사용 가능한 모델 목록을 조회.

### 4. 키워드 추출 버그 수정
붙여넣은 제목 목록 첫 줄을 무조건 검색 키워드로 쓰던 로직 때문에, 헤더 문구("검색어로 유입된
게시물")나 순번 줄이 섞여 들어오면 엉뚱한 주제로 검색되는 버그 발견. 순번만 있는 줄은 제거하고,
제목들 전체에서 빈도 기반으로 공통 핵심 키워드를 추출하도록 수정(`clean_title_lines`,
`extract_main_keyword`).

### 5. 프롬프트 3단계 재구성
기존 "초안 작성(경험 지어내기 포함) → 윤문" 2단계에서, 정보와 경험을 분리한 3단계로 변경:
1. **정보 초안** — 경험 없이 사실 정확도·구조·대안 비교에만 집중. 키워드 스터핑 금지 조항 추가.
2. **경험 관점 입히기(신규)** — 완성된 정보 초안을 보고 5가지 경험 서술 방식 중 하나를 골라 도입부/각
   소제목/결론에 경험의 결을 얹음. 기존 사실·수치는 절대 변경 금지.
3. **im-not-ai 윤문** — 기존과 동일하게 톤 다듬기.

### 6. 라이트 테마로 전환
어두운 Catppuccin 스타일 → 화이트/라이트 그레이 배경 + 블루-퍼플 그라데이션 포인트 컬러로 전체
스타일시트 교체.

### 7. 예약 작업 큐 기능
"✍️ 글 작성" 탭에 "➕ 새 작업 예약 추가" 버튼과 예약 작업 목록(`QListWidget`)을 추가. 현재 작업이
실행 중이어도 이 버튼을 누르면 `AddTaskDialog`(제목 입력 + 이미지 옵션 체크박스 + "확인" 버튼)가 떠서
다음 글감을 입력하고 큐에 쌓을 수 있다. 진행 중인 작업이 없을 때는 즉시 실행되고, 있을 때는 대기했다가
현재 작업의 `finished_signal`/`error_signal` 콜백에서 `try_start_next_job()`이 자동으로 다음 큐 항목을
꺼내 이어서 실행한다(`MainWindow.job_queue`, `run_job`, `try_start_next_job`, `on_add_task`,
`refresh_queue_list`, `on_remove_task`). 큐 항목은 목록에서 선택 후 "🗑️ 선택 삭제"로 제거 가능.

### 8. 작업별 결과물 폴더 분리
기존에는 `preview.html`/`thumbnail.png`/`image_N.png`가 모두 프로젝트 루트에 그대로 덮어써졌음.
`BlogGeneratorThread.make_job_dir()`을 추가해 `results/{타임스탬프}_{제목앞부분}/` 형태의 작업별
폴더를 생성하고, `self.output_dir`과 `Html2Image(output_path=...)`를 이 폴더로 지정. 이제 각 작업의
HTML과 이미지가 서로 덮어쓰지 않고 별도 폴더에 남는다(예약 작업을 연속 실행해도 결과물이 섞이지 않음).

### 9. 썸네일 1:1 비율 1080px로 변경
기존에는 썸네일도 소제목 카드와 동일하게 800x450(16:9 계열)로 캡처됨. `capture_html`에 `size`
파라미터를 추가해 캡처 시점에 크기를 오버라이드할 수 있게 하고, 썸네일 생성 시에만 LLM 프롬프트의
카드 크기 규칙을 `1080px x 1080px 고정 (1:1 정사각형)`으로 바꾸고 `Html2Image` 캡처도
`size=(1080, 1080)`으로 호출하도록 수정. 소제목 카드는 기존 800x450 그대로 유지.

### 10. 설정 탭 - 모델 자동 조회 제거 → 수동 입력 + 공급자별 모델 목록 페이지 바로가기
한때 "모델 업데이트" 버튼으로 공급자 API에서 실사용 가능 모델 목록을 자동 조회해 체크박스로
선택하게 했었으나(`providers.list_models`, 응답 rate-limit 헤더 기반 잔여 할당량 표시 포함),
프록시/공급자별 응답 형식 차이로 실제로는 목록을 못 불러오는 문제가 발생해 이 방식을 완전히 제거함.

대신 모델명은 `QLineEdit`(`input_model`)에 직접 입력하는 방식으로 되돌리고, 그 옆에
"🔗 {공급자명} 모델 목록 보기" 버튼(`btn_model_link`, `on_open_model_page`)을 추가해 클릭 시
해당 공급자의 공식 모델 목록 문서를 브라우저로 연다(`providers.PROVIDER_MODEL_PAGES`):
- Claude → docs.anthropic.com 모델 개요 페이지
- Gemini → ai.google.dev 모델 목록 페이지
- ChatGPT → platform.openai.com/docs/models
- Ollama → ollama.com/library

공급자를 바꾸면 버튼 라벨과 이동할 링크도 함께 갱신된다(`load_provider_fields`). `ModelFetchThread`,
`list_models()`, 할당량 파싱 로직은 모두 삭제됨(죽은 코드로 남기지 않음).

### 11. Gemini "400 API key not valid" 오류 원인 파악 및 수정
사용자가 공유한 실행 화면 스크린샷에서 `Step 1/5`(15%) 단계 중
`400 Client Error ... generativelanguage.googleapis.com/v1beta/models/gemini-3.1-flash-lite:gen...`
오류 발생. `config.json`을 직접 열어보니 Gemini API 키에 백슬래시가 섞여 있었음
(`AIzaSyBUqDt\_0Soq6UthPM-ra0TPMnEBfS0-mUI`) — 마크다운 이스케이프(`\_`)가 포함된 텍스트를
복사해서 설정 탭에 붙여넣을 때 백슬래시까지 같이 들어간 것으로 추정. 실제로 이전 라운드에서
"모델 목록을 못 불러온다"고 판단해 자동 조회 기능(10번 항목)을 걷어냈었는데, 재현해보니
모델명(`gemini-3.1-flash-lite`)도 실존하고 API 자체도 정상 응답했고, 문제는 이 손상된 키
하나였음(백슬래시를 제거하니 모델 목록 조회·generateContent 호출 모두 200 정상).

`config.json`의 키를 직접 수정해 문제를 해결했고, 재발 방지를 위해
`SettingsTab.stash_current_fields()`에서 API 키 저장 시 백슬래시를 자동으로 제거하도록
방어 코드를 추가함(어떤 공급자의 API 키 형식에도 백슬래시가 정상적으로 포함되는 경우는 없음).

### 12. 실행 로그 패널 + log.txt — 실제 크롤링/검색 건수 확인
"네이버 블로그 3개를 실제로 긁어오는지, 뉴스 5개를 실제로 불러오는지" 확인하고 싶다는 요청으로 추가.
`BlogGeneratorThread.log()` 헬퍼를 만들어 기존 `progress_signal.emit(...)` 호출을 전부 이걸로 교체 —
UI로 메시지를 보내는 동시에 작업 폴더의 `log.txt`에도 타임스탬프와 함께 기록한다.

`crawl_naver_blogs()`와 `search_naver()`에 상세 로그를 추가해 실제 처리 건수를 확인할 수 있게 함:
- 블로그: 후보 URL 개수 → 중복 제거 후 크롤링 시도 개수 → URL별 성공(글자 수)/실패/본문없음 → 최종
  성공 건수
- 뉴스: 요청한 display 값 대비 실제 응답받은 건수, 각 기사 제목 나열

실제 네이버 API로 검증한 결과 블로그 3개(성공 3/3), 뉴스 5개(응답 5건) 모두 설정대로 정확히
동작함을 확인함.

"✍️ 글 작성" 탭 하단에 "🪵 실행 로그" 패널(`log_view`, 읽기 전용 `QTextEdit`)을 추가해 위 로그가
실시간으로 누적 표시되며, "📄 로그 파일 열기" 버튼(`open_log_file`)으로 해당 작업의 `log.txt`를
브라우저로 열어볼 수 있다. 작업이 시작되는 시점(`run_job`)에 로그 파일 경로가 바로 정해지므로,
실행 중에도 로그 파일을 열어 진행 상황을 확인할 수 있다.

### 13. 출력물 부실/과도한 축소 문제 원인 파악 및 수정
사용자가 "수집한 글이 많아지니 출력물이 부실해진다"고 제보. 실제 저장된 결과물(`preview.html`)을
열어 본문 글자수를 재보니 목표(2000~2500자)의 62%인 1,544자밖에 안 됐음. 처음엔 입력 토큰 과다를
의심했으나, `search_context`는 3,800~4,200자 수준으로 어떤 모델에도 부담될 크기가 아니었음.

실제 원인을 찾기 위해 정보 초안→경험 관점→윤문 3단계 각각의 글자수를 로그로 찍어 비교한 결과,
**4단계 "im-not-ai 윤문" 프롬프트가 "말투를 다듬어라"고만 지시하고 "줄이지 마라"는 말이 없어서**,
가벼운 모델(`gemini-3.1-flash-lite`)이 문장을 다듬으면서 내용을 함께 쳐내는 것이 원인이었음. 같은
검색 결과로 재현했을 때 수정 전 최종본은 1,544자, 수정 후에는 2,517자로 확인됨.

적용한 수정:
1. 경험 관점 프롬프트(`prompt_experience`)의 `[반드시 지킬 것]`에 "경험 문장은 추가하는 것이지
   대체가 아니다. 요약/축소 금지, 원문 분량 이상으로 늘어나야 정상" 규칙 추가.
2. 윤문 프롬프트(`prompt_proofread`)의 `[윤문 규칙]`에 "말투만 바꾸는 작업. 문장/문단 삭제·요약으로
   분량을 줄이지 말 것. 결과물은 원문과 비슷하거나 더 길어야 함" 규칙 추가.
3. 윤문 단계 `call_api`의 `max_tokens`를 3000 → 3500으로 상향(출력 토큰 부족으로 인한 잘림 가능성
   원천 차단).
4. 정보 초안/경험 관점/윤문 각 단계 완료 시 실제 글자수를 `self.log()`로 남기도록 추가 — 다음부터는
   어느 단계에서 분량이 줄었는지 `log.txt`/실행 로그 패널에서 바로 확인 가능.

### 14. 제목이 마침표로 끝날 때 결과 폴더 생성 실패 (FileNotFoundError) 수정
"장윤정 모친 연락두절... 마지막 편지 논란.." 같이 제목이 마침표(생략부호 등)로 끝나는 경우,
`capture_html`에서 `[Errno 2] No such file or directory: ..._temp_thumbnail.png.html` 오류로
실행이 중단됨. 원인은 `make_job_dir()`의 폴더명 정리 로직이 마침표/공백을 끝에서 제거하지
않았던 것 — Windows는 폴더/파일명이 마침표나 공백으로 끝나는 것을 허용하지 않고 자동으로 잘라서
저장하므로(`...논란..` → 실제로는 `...논란`), `os.makedirs()`가 만든 실제 폴더명과 파이썬이 들고
있는 `self.output_dir` 문자열이 어긋나 이후 그 안에 파일을 열 때마다 실패했음.

`make_job_dir()`에서 폴더명을 30자로 자른 뒤 `.rstrip('. ')`로 끝의 마침표·공백을 제거하도록 수정.
동일한 제목으로 재현 후 폴더가 정상 생성되고 그 안에 파일을 쓸 수 있음을 확인함.

### 15. 키워드 추출 - 파생어끼리 표가 갈려 엉뚱한 검색어가 뽑히는 문제 수정
사용자가 "감자 보관법" 관련 제목 19개를 넣고 돌린 로그를 보니, 뉴스 검색 결과가 "톱모델 다이어트
식단", "'뜨거운 감자' 관용구(사관학교 통합 이슈)"처럼 보관법과 전혀 무관한 기사들로 채워짐.

원인 확인: `extract_main_keyword`가 "가장 많이 등장한 단어 1개"만 뽑는 방식인데, 실제 토큰 빈도를
세보면 `감자(15) > 보관방법(10) > 보관법(7) > 보관(5)`처럼 진짜 주제어인 "보관" 계열이 철자
변형(보관/보관법/보관방법/보관하는 등) 때문에 표가 갈려서, 사실상 모든 제목의 핵심 주제인데도
단독으로는 "감자"보다 적게 得표해 검색어가 "감자"로만 뽑혔던 것.

`extract_main_keyword`를 다음과 같이 수정:
1. 토큰들을 빈도 내림차순으로 정렬하며, **공통 접두어가 2글자 이상**인 토큰들을 같은 개념
   그룹으로 합산(`os.path.commonprefix` 이용) — "보관/보관법/보관방법/보관하는" 등이 전부
   "보관" 그룹으로 합쳐짐.
2. 합산 후 득표 상위 2개 개념(각각 2회 이상 등장한 것만)을 뽑아, 제목에 등장하는 순서대로
   재배열해 자연스러운 구(句)로 조합(`"감자 보관"`, `"보관 감자"`가 아니라 원문 순서를 따름).
3. 상위 개념이 1개뿐이거나 없으면 기존과 동일하게 폴백(단일 키워드 또는 첫 줄 전체).

실제 데이터로 검증: 키워드가 `감자` → `감자 보관`으로 바뀌었고, 이 키워드로 다시 뉴스를 검색해보니
"감자 껍질 벗긴 뒤 '이렇게' 보관하면 갈변 늦출 수 있다" 같은 실제 보관법 기사가 잡히기 시작함
(기존 "감자" 단독 검색은 5개 전부 무관한 기사였음). 클로드/기후동행카드 등 기존에 잘 동작하던

  수정. 셀렉터 상수에 부분 일치 금지 경고 주석 추가.
- **번호/불릿 목록 중복 표기**: "1. "을 타이핑하면 에디터가 자동 번호목록으로 변환해 이후

### 22. 네이버 클립용 카드뉴스 슬라이드쇼 영상 자동 생성
SNS 패키지에서 만든 카드뉴스를 이어붙여 네이버 클립(세로 숏폼)용 mp4를 자동 생성.
Opus Worker 위임 + Advisor 직접 검증(테스트 75건 실행, ffprobe 스모크 재확인).

- **설계 결정**: 정사각 카드를 레터박스로 감싸는 대신 **세로형(1080×1920) 재렌더** —
  `sns_package.py` 템플릿이 flex 중앙정렬이라 크기 파라미터화만으로 자연 적응. 영상 조립은
  PATH에 이미 있는 ffmpeg 8.1.1을 subprocess 직접 호출(신규 파이썬 의존성 0). 오디오는
  v1에서 BGM 옵션(설정에서 파일 지정, 미지정 시 무음, 클립 앱에서 음악 추가 가능 전제),
  TTS 나레이션은 다음 단계 후보.
- **`sns_package.py`**: `render_cover/render_content/render_last`에 선택적 `size` 파라미터
  추가(기본값은 기존 1080×1080 그대로 — 기존 호출·테스트 무영향), `CLIP_SIZE=(1080,1920)`.
- **`video_maker.py` 신설** (PyQt5 무의존, 표준 라이브러리+ffmpeg subprocess만):
  - `build_ffmpeg_cmd()` 순수 함수 — `-loop 1 -t {dur} -i` 입력 + scale/setsar/fps 정규화 +
    xfade 크로스페이드 체인(i번째 전환 offset = sum(d0..d_{i-1}) − i·xfade), 1장이면 xfade
    생략. 출력 libx264/yuv420p/faststart/30fps. BGM 시 `-stream_loop -1`+`-shortest`+aac,
    끝 1.5초 afade 아웃.
  - `make_clip()` — shell=False 리스트 인자(한글 경로 안전), ffmpeg 부재/실패 시 명확한 예외.
  - `total_duration()` = sum(dur) − (n−1)·xfade. 기본 노출: 표지 3.0초/본문 4.5초/마지막 3.5초,
    xfade 0.5초 (카드 4장 기준 총 ~22초).
- **main.py 통합**: SNS 패키지 성공 후 `make_clip` 옵션 시 세로형 `sns_v_cover.png`/
  `sns_v_card_N.png`/`sns_v_last.png` 추가 캡처 → `sns_clip.mp4` 생성(별도 try/except,
  블로그/SNS 결과 무영향). 글 작성 탭+AddTaskDialog에 "🎬 클립 영상 만들기" 체크박스
  (기본 켜짐, SNS 체크 해제 시 비활성화 연동). 설정 탭에 BGM 파일 입력란+찾아보기 버튼,
  config.json `video.bgm_path` 저장(`DEFAULT_CONFIG` 및 구버전 config setdefault 방어 포함).
  BGM 경로가 존재하지 않으면 경고 후 무음 진행.
- **검증**: 단위 테스트 75건 전체 통과(신규 `test_video_maker.py` 19건 — xfade 오프셋 수치,
  BGM 유무 인자, afade 시각, 세로 렌더). 실 ffmpeg 스모크(Advisor 직접 재실행): 3장
  [3.0/4.5/3.5초] → 1080×1920 h264 yuv420p, 길이 10.03초(계산값 10.0초 일치). BGM 케이스는
  4초 sine이 `-stream_loop`로 10.03초 aac 트랙으로 정상 연장됨을 ffprobe로 확인.

### 24. 클립 영상 TTS 나레이션 (edge-tts)
카드뉴스 슬라이드쇼 mp4에 카드 텍스트를 읽어주는 한국어 나레이션을 추가.

  "제목. 본문" / "요약. CTA") — v1 결정, LLM 전용 대본은 v2 후보.

  `probe_duration`(ffprobe subprocess), `DEFAULT_VOICE`/`VOICES`(선히·인준·현수).
- **`video_maker.py` 확장**: `build_ffmpeg_cmd`/`make_clip`에 `narrations=[(mp3, start_sec),...]`
  파라미터 — adelay(양채널)+amix(normalize=0, 나레이션 볼륨 유지)+apad+`-shortest`, BGM 동시
  사용 시 volume=0.2 덕킹(afade 아웃 유지), 나레이션만 있어도 aac 인코딩. `narrations=None`이면
  기존 인자와 완전 동일(회귀 가드 테스트 있음). `plan_narrated_slides` 순수 함수 —

### 26. Step 0 — 메인키워드·논조·소제목 LLM 분석 + 제목-메인키워드 결합 규칙 (사용자 결정)

  포함 여부를 확인해, 공백 유무 차이는 허용하되 키워드 중간에 다른 단어가 끼면 정확히 걸러낸다.

  마커 응답을 파싱하고, 마커가 없거나 파싱 실패 시 기존 `extract_main_keyword` 결과로 안전하게 폴백.

  추천 개요), 제목 규칙에 모두 사용됨. 응답 파싱 실패 시 경고 로그 후 기존 파이썬 빈도 기반 키워드로

- **제목 규칙 + 재시도**: `prompt_draft`에 "메인키워드를 중간에 다른 단어 삽입 없이 통째로 포함"

### 27. PyQt5 실행 오류(qt.conf 유실) 자동 우회 + 윤문 프롬프트 고도화
사용자 실행 환경(Python 3.13)에서 `qt.qpa.plugin: Could not find the Qt platform plugin "windows"`로
앱이 아예 안 뜨는 문제 발생. `QT_DEBUG_PLUGINS=1`로 원인 확인: PyQt5-Qt5 wheel에 있어야 할
`qt.conf`가 없어(백신 격리/불완전 설치 추정) Qt가 플러그인 폴더 위치를 스스로 못 찾고
`<파이썬설치경로>/platforms`(엉뚱한 곳)만 검색하고 있었음. `QT_QPA_PLATFORM_PLUGIN_PATH`를
PyQt5의 실제 `Qt5/plugins/platforms` 경로로 수동 지정하니 정상 로드되는 것으로 원인 확정.

- **`main.py` 최상단**: PyQt5 import 직전에 `import PyQt5` 후 `os.path.dirname(PyQt5.__file__)`
  기준으로 `Qt5/plugins/platforms` 경로를 계산해 존재하면 `os.environ.setdefault(
  "QT_QPA_PLATFORM_PLUGIN_PATH", ...)`로 자동 지정. 하드코딩된 절대경로 없이 어떤 컴퓨터/실행
  방식(더블클릭, run.bat, `python main.py`)에서도 동일 문제를 자동 우회.
- 사용자 확인: 이 수정 후 별도 환경변수 설정 없이 정상 실행됨.
- **윤문 프롬프트(`prompt_proofread`) 전면 교체**: 사용자가 다른 프로젝트에서 쓰던 전문
  카피에디터 프롬프트(번역투/AI 상투구/과장 어휘 제거, 로봇식 나열·접속사 남발·이중피동 교정,
  가독성/리듬 개선 등 상세 체크리스트)를 이 앱 맥락에 맞게 병합 적용. 기존 "찐후기 평어체" 톤
  유지 규칙은 존치, "출력에 제목 포함" 지시는 제외(이 호출엔 본문만 들어가고 제목은 별도 관리),
  분량 유지·수치 보존 규칙은 기존 13번 항목의 회귀 사고 방지 차원에서 그대로 강조 유지, 표
  보존 규칙은 축약해 방어적으로 추가.

### 28. SNS 카드뉴스 표지에 리터럴 "\n" 글자가 그대로 노출되던 버그 수정
사용자가 sns_cover.png 스크린샷 제보: 표지 문구 줄바꿈 위치에 실제 줄바꿈 대신 "\n" 글자 2개가
그대로 찍혀 나옴.

- **원인**: `build_sns_prompt`의 표지 문구 규칙이 "두세 단어 단위로 줄바꿈(\n)을 넣어"라고
  지시하는데, 일부 응답에서 LLM이 실제 개행 문자 대신 백슬래시+n 두 글자를 문자 그대로
  출력함. `sns_package._escape_and_mark`는 실제 개행 문자(`"\n"`)만 `<br>`로 바꿨기 때문에,
  리터럴 두 글자 시퀀스는 그대로 통과해 화면에 노출됨.
- **수정**: `_escape_and_mark`에서 html.escape 이전에 `raw_text.replace("\\n", "\n")`으로
  리터럴 백슬래시+n을 실제 개행으로 먼저 정규화. `render_cover`/`render_content`/`render_last`가
  전부 이 함수를 공유해서 쓰므로 표지뿐 아니라 카드 제목/본문/마지막 요약·CTA에서도 동일하게
  방어됨.
- **검증**: `test_sns_package.py`에 회귀 테스트 1건 추가(리터럴 `\n` 입력 → `<br>` 변환 확인,
  화면에 `\n` 텍스트가 남지 않는지 확인). 전체 단위 테스트 54건(`test_textutils`,
  `test_sns_package`, `test_naver_keywords`) 통과.

### 29. 마크다운 표(테이블)가 네이버 붙여넣기 시 깨지던 문제 수정
사용자 제보: "html로 작성이 되는데, 네이버 블로그에 붙여넣으니 표가 들어가지지 않는다. 스마트에디터ONE에서
직접 작성한 것처럼 붙여넣어도 서식 문제없게 해달라."

- **원인**: `textutils.format_for_naver`가 마크다운 표(`| 항목 | 값 |` + `|---|---|` 구분선)를 전혀
  인식하지 못해 표의 각 줄을 그냥 `<p>` 문단으로 출력함. 브라우저 미리보기에서 Ctrl+A/C로 복사해
  네이버 에디터에 붙여넣는 흐름(사용자가 실제 쓰는 방식)에서 표 구조가 사라지고 파이프(`|`) 기호가
  텍스트로 그대로 노출됨.
- **수정**(`textutils.py`): `_is_table_row`/`_is_table_separator`/`_split_table_row`/`_render_table`
  추가. 헤더 행 바로 다음 줄이 `|---|---|` 구분선이면 표 블록으로 인식해 실제 `<table><th>...<td>`
  HTML로 변환(셀마다 inline style 직접 부여 — 외부 CSS는 복사 시 함께 안 딸려가므로). 셀 안
  `**볼드**`도 함께 변환. 구분선이 없는 단순 파이프 포함 문장은 오탐 없이 기존처럼 `<p>` 처리.
- **프롬프트 보강**(`main.py` `prompt_draft`): "가격/스펙/일정처럼 항목별로 비교·정리하는 내용은
  마크다운 표로 정리하라"는 규칙 추가(억지로 표를 만들지 말라는 단서 포함). 기존 윤문 프롬프트에
  이미 있던 "표가 있으면 격자 구조 유지" 규칙은 그대로 유지됨.
- **검증**: `test_textutils.py`에 표 변환 회귀 테스트 2건 추가(정상 변환 + 파이프만 있고 구분선 없는
  문장 오탐 방지), 전체 단위 테스트 109건 통과. **사용자가 실계정으로 미리보기→복사→붙여넣기 직접
  테스트해 표가 정상적으로 붙여넣어짐을 확인함.**

### 30. 제목 작성 모드 분리 — 홈판용(클릭 유도형) / 정보 전달용(SEO형)

    이해 가능)·모바일 문장 길이 조절 규칙을 `[작성 규칙]`에 추가. 정보전달용은 목표 분량이 커서
    `call_api max_tokens`도 5000→7000으로 상향(초안·윤문 둘 다).

  - 윤문 프롬프트: 홈판용은 기존 im-not-ai(반말 찐후기 톤) 그대로. 정보전달용은 신규 존댓말
