# 제목 작성 모드 (홈판용 / 정보 전달용) 설계

작성일: 2026-07-08

## 배경 / 목적

현재 `BlogGeneratorThread`는 제목·본문을 한 가지 방식(정보 초안 → 경험 관점 오버레이 → im-not-ai
윤문, 반말체, 2000~2500자)으로만 생성한다. 사용자는 목적에 따라 제목 작성 전략을 두 갈래로 나누고
싶어한다.

- **홈판용**: 네이버 메인(홈판) 노출을 노리는 클릭 유도형 제목. 4가지 후킹 패턴 중 글감에 맞는 것을
  LLM이 자율 선택.
- **정보 전달용**: SEO 지향. 메인키워드를 제목 맨 앞에 배치하고, 검색 결과에서 뽑은 연관어를 붙인다.
  본문도 존댓말·쉬운 설명·모바일 친화적 문장 길이로 별도 톤을 쓴다.

두 모드는 메인 화면(글 작성 탭)과 예약 작업 큐(AddTaskDialog)에서 라디오버튼으로 선택한다.

## 범위

- 글 작성 탭 + AddTaskDialog에 라디오버튼 2개(상호배타적) 추가, 작업 데이터에 `title_mode` 필드 추가
- `BlogGeneratorThread.run()`의 크롤링 개수·프롬프트·파이프라인 단계 수를 `title_mode`에 따라 분기
- `textutils.py`에 `title_starts_with_keyword()` 추가 + 정보 전달용 제목 재시도 로직
- SNS 패키지·클립 영상·TTS 등 기존 체크박스 기능은 범위 밖(변경 없음, title_mode와 독립적으로 계속 동작)

## 설계

### 1. UI

- **글 작성 탭**: 라디오버튼 2개를 `QButtonGroup`으로 묶어 이미지 옵션 체크박스들 근처에 추가.
  - `🏠 홈판용 (클릭 유도형)` — 기본 선택(체크된 상태로 시작)
  - `📖 정보 전달용 (SEO형)`
- **AddTaskDialog**: 동일한 라디오버튼 쌍 추가. 다이얼로그를 여는 시점에 메인 화면에서 현재 선택된
  모드를 기본값으로 물려받는다(기존 `default_thumbnail` 인자 패턴과 동일하게 `default_title_mode`
  인자를 생성자에 추가).
- `run()`에 전달되는 작업 딕셔너리(`self.chk_thumbnail.isChecked()` 등을 모으는 곳)에
  `"title_mode": "home" | "info"` 필드를 추가한다.

### 2. 생성 파이프라인 분기 (`BlogGeneratorThread.run`)

| 구분 | 홈판용 (기존 유지) | 정보 전달용 (신규) |
|---|---|---|
| 블로그 크롤링 개수 | 3개 | 5개 |
| 뉴스 검색 개수 | 5개 | 5개 (동일) |
| 제목 규칙 | 4가지 후킹 패턴(①반전/②손해회피/③내돈내산/④가성비리스트) 중 LLM이 글감에 맞게 자율 선택 + 메인키워드 통째 포함 규칙 유지 | 메인키워드를 제목 맨 앞에 배치 + `search_context`(뉴스·블로그 검색결과)에서 LLM이 직접 연관어를 뽑아 붙임 |
| 파이프라인 단계 | 기존 3단계 그대로: 정보초안 → 경험 관점 오버레이 → im-not-ai 윤문(반말, 2000~2500자) | 2단계로 축소: 정보초안(존댓말·2500~5000자·쉬운 설명·모바일 줄바꿈 고려) → 존댓말 윤문. 경험 관점 오버레이 단계는 생략 |
| 톤 | 기존 찐후기 반말체 | 존댓말, 어린이도 이해하기 쉬운 설명, 문장은 모바일 가독성을 고려해 적당히 끊어서 작성 |

세부 사항:
- `prompt_draft`는 `title_mode`에 따라 [제목 규칙] 섹션과 (정보전달용의 경우) 톤/분량/난이도 규칙을
  분기해서 구성한다. 기존 홈판용 프롬프트 문구는 최대한 그대로 재사용하고, 제목 규칙 섹션만 4가지
  패턴 설명으로 교체한다.
- 정보 전달용은 별도 존댓말 윤문 프롬프트(`prompt_proofread_info`)를 신설한다. 기존
  `prompt_proofread`(반말·im-not-ai 스타일)는 홈판용 전용으로 그대로 둔다.
- 진행 로그(`Step N/M`)는 모드별로 총 단계 수가 다르므로(정보전달용은 경험 단계가 빠져 한 단계 적음)
  분기해서 표시한다.
- H2 소제목 카드 이미지, SNS 패키지, 클립 영상, TTS 나레이션 등 나머지 기능은 title_mode와 무관하게
  완전히 독립적으로 동작한다 — 최종 윤문 텍스트를 그대로 입력받아 기존 로직 그대로 진행한다(수정 없음).

### 3. 제목 검증 로직

- `textutils.py`에 `title_starts_with_keyword(title, keyword)` 신규 추가. 공백을 제거한 뒤 title이
  keyword로 시작하는지 확인한다(기존 `title_contains_keyword`와 짝을 이루는 함수, 같은 정규화 방식
  재사용).
- 정보 전달용은 이 함수로 검증하고, 위반 시 별도 재시도 프롬프트(맨 앞 배치 규칙을 명시한
  `prompt_fix_title_info`)로 최대 2회 재시도한다. 재시도 후에도 실패하면 경고 로그만 남기고 진행한다
  (기존 홈판용 재시도 정책과 동일 — 실패해도 파이프라인은 중단하지 않는다).
- 홈판용은 기존 `title_contains_keyword`(통째 포함) 검증 + `prompt_fix_title` 재시도를 그대로 유지한다.

### 4. 테스트

- `test_textutils.py`에 `title_starts_with_keyword` 단위 테스트 추가 (정상 케이스, 맨 앞이 아닌 경우
  실패, 공백 유무 허용 케이스).

## 비범위 (Out of scope)

- 4가지 홈판 패턴을 사용자가 직접 선택하는 UI (LLM 자율 선택으로 확정)
- 연관 키워드를 검색광고 API 등 외부 데이터로 검증하는 것 (검색 컨텍스트 기반 LLM 자체 판단으로 확정)
- SNS 패키지/클립 영상 로직에 title_mode 반영 (완전히 독립적으로 유지)
