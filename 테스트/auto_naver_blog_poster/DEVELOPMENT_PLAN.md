## 1. 현재 프로그램 구조 (코드 정밀 점검 결과)

### 1.1 파일 구성
| 파일 | 역할 | 규모 |
|---|---|---|
| `main.py` | PyQt5 UI 전체 + 생성 파이프라인(`BlogGeneratorThread`) + 설정 탭 + 예약 큐 | ~1,000줄 |
| `providers.py` | Claude/Gemini/ChatGPT/Ollama 통합 `chat()` 어댑터 (재시도 포함) | ~90줄 |
| `config_manager.py` | `config.json` 로드/저장, 기본값 보강 | ~50줄 |
| `test_api.py`, `test_models.py` | 일회성 수동 확인 스크립트 (자동 테스트 아님) | - |

### 1.2 생성 파이프라인 (BlogGeneratorThread.run)
```
입력: 참고 블로그 제목 목록 (여러 줄)
 ① 제목 정제 + 빈도 기반 핵심 키워드 추출 (clean_title_lines, extract_main_keyword)
 ② 네이버 모바일 검색 크롤링(블로그 상위 3개 본문) + 뉴스 API 5건 → search_context
 ③ LLM 3단계: 정보 초안(제목+본문+해시태그30개) → 경험 관점 오버레이 → im-not-ai 윤문
 ④ H2 소제목 추출 → 소제목별 인포그래픽 HTML 카드 생성(LLM) → Html2Image로 PNG 캡처
    (썸네일 1080x1080, 소제목 카드 800x450)
 ⑤ 마크다운 → 네이버용 HTML 변환(format_for_naver) → preview.html 저장
출력: results/{타임스탬프}_{제목}/ 폴더에 preview.html + thumbnail.png + image_N.png + log.txt
```

### 1.3 UI 구성
- **글 작성 탭**: 제목 입력 / HTML 소스 출력 / 이미지 on-off 체크박스 / 실행·예약추가·미리보기·로그 버튼 / 예약 큐 목록 / 진행바 / 실행 로그 패널
- **설정 탭**: 공급자 선택, API 키(백슬래시 자동 제거), Base URL, 모델명 직접 입력 + 공식 모델 목록 링크

## 2. 발견된 문제점

### 2.1 알려진 이슈 (progress.md 기재)
- **[P1] 이미지 alt 텍스트 노출 버그** — 이미지 자리에 "썸네일"/"소제목 이미지" 텍스트만 표시됨
- **[P2] 경험 오버레이 실효성 부족** — 7개 섹션 중 2개만 반영, "~인 줄 알았는데" 문형 반복
- **[P3] Gemini/ChatGPT/Ollama end-to-end 미검증** — Claude 프록시로만 검증됨

### 2.2 이번 코드 점검에서 신규 발견 (progress.md에 없음)

- **[N1] alt 버그 원인 후보 확인됨**
  - (a) 프로젝트 루트에 구버전 `preview.html`(2026-07-04 생성, 작업 폴더 분리 이전 산출물)이 남아 있고, `thumbnail.png`/`image_1~6.png`를 상대경로로 참조하지만 루트에 PNG가 없음 → 이 파일을 열면 증상 100% 재현. **루트의 legacy preview.html 삭제 필요.**
  - (b) 구조적 한계: 브라우저에서 Ctrl+A/C로 복사해도 `file://` 로컬 이미지는 네이버 스마트에디터(웹)에 붙여넣어지지 않음 → 에디터 안에서 alt 텍스트로 표시될 수밖에 없음. **이미지는 별도 첨부하는 UX로 재설계 필요** (예: "결과 폴더 열기" 버튼 + 이미지 드래그&드롭 안내).
  - (c) 이미지 카드 LLM 응답이 `max_tokens=1500`으로 잘리면 \`\`\`html 블록 정규식 매칭 실패 → 카드가 **조용히 스킵**됨(`continue`, 로그 없음). 실패 로그 추가 필요.

- **[N2] 시크릿 하드코딩**
  - `main.py:20-21` 네이버 Client ID/Secret 소스에 노출
  - `config_manager.py:10` Claude 프록시 API 키가 DEFAULT_CONFIG에 평문 포함
  - → 전부 `config.json`으로 이동, 소스에서 제거

- **[N3] 예약 큐 잠금(deadlock) 경로**
  - `on_finished`에서 큐가 남아 있으면 `btn_run`을 재활성화하지 않은 채 `try_start_next_job()` 호출 → 다음 작업 시작이 실패하면(API 키 삭제 등) 작업은 큐로 복귀하지만 **실행 버튼이 영구 비활성** → 재시작 전까지 조작 불가
  - `finished_signal` 수신 시점에 워커 스레드가 아직 `isRunning()`일 수 있는 미세한 레이스 → 다음 큐 작업이 시작되지 않을 가능성

- **[N4] HTML 변환기 결함**
  - `format_for_naver`가 `<li>`를 `<ul>` 래핑 없이 출력 → 붙여넣기 시 목록 서식 깨질 수 있음
  - 마크다운 링크/인용 등 미지원 (현재 프롬프트상 발생 빈도는 낮음)

- **[N5] 응답 파싱 방어 부족**
  - Gemini: `candidates[0].content.parts[0].text` 직접 접근 → 세이프티 차단/MAX_TOKENS 종료 시 parts가 없어 KeyError로 죽음 (오류 메시지가 원인을 안 알려줌)
  - 해시태그 30개 요구를 검증하지 않음 (모델이 15개만 주면 그대로 출력)

- **[N6] max_tokens 여유 부족 가능성**
  - 한국어 2,000~2,500자는 대략 3,000~4,000 토큰. 초안/경험/윤문 단계의 `max_tokens=3500`은 경계선 → 긴 글에서 잘림 위험. 4,500~5,000으로 상향 검토

- **[N7] 운영 편의 부족**
  - 실행 중 작업 취소 버튼 없음
  - 예약 큐가 앱 재시작 시 소실됨
  - "결과 폴더 열기" 버튼 없음 (이미지 수동 첨부 UX에 필수)
  - 자동 테스트 없음 (키워드 추출·HTML 변환은 순수 함수라 단위 테스트 가능)

### Phase 1 — 황금키워드 발굴 (키워드 인사이트 탭)
사용자 결정: 검색광고 API 계정 가입 진행 (무료, searchad.naver.com)

- **데이터 소스**
  - 네이버 검색광고 API `keywordstool`: 키워드별 **월간 검색량 절대치**(PC/모바일) + 연관 키워드 확장 — 황금키워드 판별의 핵심
  - 네이버 검색 API: 키워드별 **블로그 총 발행문서 수**(경쟁 지표)
  - (선택) 데이터랩 API: 검색량 추이 그래프 (상승/하락 트렌드)
- **황금키워드 지표**: `월간 검색량 ÷ 블로그 발행량` 비율 기반 점수화 + 등급(A/B/C) 표시 — Blog Factory V4의 "키워드 등급/진입 가능성"과 동일 원리
- **UI**: 신규 "🔑 키워드 분석" 탭 — 시드 키워드 입력 → 연관 키워드 수십 개를 검색량·발행량·점수와 함께 테이블로 표시, 정렬/필터 지원
- **연동**: 테이블에서 키워드 선택 → "이 키워드로 글 쓰기" 버튼 → 글 작성 탭으로 키워드 전달 (핵심 루프의 시작점)
- **설정**: 검색광고 API 키(Customer ID / Access License / Secret) 입력란을 설정 탭에 추가

### Phase 2 — 네이버 자동 포스팅 (임시저장 방식)
사용자 결정: 완전 자동 발행이 아닌 **임시저장까지 자동화 → 사용자가 검토 후 발행 버튼 클릭** (저품질·오발행 위험 최소화)

- **방식**: Playwright 브라우저 자동화 (공식 글쓰기 API 폐지로 상용 툴들도 동일 방식)
  - 최초 1회: 브라우저 창을 띄워 사용자가 직접 네이버 로그인 → 세션(storage state) 저장
  - 이후: 저장된 세션으로 스마트에디터원 자동 조작 — 제목 입력, 본문 서식(소제목/굵게) 입력, **이미지 파일 직접 업로드**, 해시태그 입력 → 임시저장
  - 세션 만료 시 재로그인 안내 (참고 스크린샷의 "네이버 로그인 세션 만료" UX와 동일)
- **효과**: 미해결 P1(이미지 붙여넣기 불가) 문제가 근본적으로 해결됨 — 자동화가 이미지를 에디터에 직접 업로드
- **안전장치**: 발행 간격 제어(연속 임시저장 사이 대기), 자동화 실패 시 기존 미리보기+수동 복사 흐름으로 폴백
- **UI**: 글 생성 완료 후 "📤 네이버 임시저장" 버튼 추가

## 4. 작업 방식
- **Advisor(메인 세션)**: 브리프 작성 → Opus Worker에게 구현 위임 → diff/테스트 직접 검증 → 승인
- 독립적인 작업(예: 0-3과 0-5)은 병렬 위임
- 각 작업 완료 시 progress.md 갱신
